# ADR 0312: Pulse-width modulation

Status: accepted, 2026-11-18.

## Context

Pulse-width modulation sweeps a square's duty while it plays. It is the classic way to make a
square sound alive in a synthesizer, and the usual way to encode a level as a pulse train in
power and motor control. The naive square (ADR 0305) fixes the duty for the whole signal.

## Decision

- **The API.**
  - Python: `pwm(duty, sample_rate, frequency, amplitude=1, phase=0)` in `waveforms`.
  - C#: `Waveforms.Pwm`, same arguments, `duty` a `ReadOnlySpan<double>`.
  - `duty` holds one value per output sample, so the output has `len(duty)` samples. That
    puts the array first, as the wavetable oscillator does.
  - Real output, `phase` in cycles.
- **The value.** `u[n]` is the oscillators' phase; `y[n] = A` for `u[n] < duty[n]`, else `−A`.
  A constant `duty` gives the naive square.
- **The rules.**
  - `duty` a 1-D real array, every value in [0, 1]. It may be empty, which gives an empty
    output, as `num_samples = 0` does for the other oscillators.
  - `sample_rate` positive and finite. `frequency`, `amplitude` and `phase` finite.
- **Naive.** Like the square, it aliases. A band-limited form can follow with the PolyBLEP
  residual of ADR 0311 at a moving falling edge.

## Consequences

- **Vectors.**
  - Expected values come from comparing `u` and `duty` in exact rationals.
  - The cases keep each `u[n]` at least `1e-9` from `duty[n]`, or exactly on it where both are
    exact in binary, so no rounding of `u` can change a sample.
  - Every value is `±A`, so the tolerance is `abs 0, rel 0`.
