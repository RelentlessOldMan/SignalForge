# ADR 0092: 2-D `.npy` arrays

Status: accepted, 2026-11-14

## Context

`read_npy` and `write_npy` ([ADR 0056](0056-npy.md)) handle 1-D arrays only. Multi-channel
captures, filter banks, spectrograms and constellation tables are naturally 2-D, and NumPy saves
them as `.npy` files of shape `(rows, columns)`, in C order by default and in Fortran order when the
array is column-major (`np.save` of a transposed array, or of one from MATLAB or Fortran code).

## Decision

- **API**: Python `read_npy_2d(path)` returns a C-contiguous 2-D `float64` or `complex128` array;
  C# `ReadNpy2D<T>(path)` returns a `T[,]` (`T` is `double` or `Complex`, as for `ReadNpy<T>`).
  `write_npy` also takes a 2-D array (C# overloads `WriteNpy(path, double[,])` and
  `WriteNpy(path, Complex[,])`). `read_npy` stays 1-D only, so its return type stays a 1-D
  array, and a 2-D file is still an error there; `read_npy_2d` of a 1-D file is an error too.
- **Reading**: the same header grammar, versions and dtypes as `read_npy` (ADRs 0088 and 0090),
  but the shape must be exactly two integers `(r, c)`, each at most 2147483591 (2^31 − 57), and the data must be
  `r × c` items. With `fortran_order: False` item `k` is row `k ÷ c`, column `k mod c`; with
  `True` it is row `k mod r`, column `k ÷ r`. Either way the result is returned in C order. Zero
  rows or zero columns are allowed, with no data.
- **Writing**: a 2-D array is written in C order, with the header
  `{'descr': '<f8', 'fortran_order': False, 'shape': (r, c), }` padded to 118 bytes as for 1-D
  (`numpy.save` writes the same bytes for these shapes). A 3-D or higher array is still rejected.
- **`.npz`**: `write_npz` and `read_npz` stay 1-D, so every archive SignalForge writes is one it
  reads. 2-D members can come later with their own reader.
- **Expected values**: the generator packs each item with `struct` in the file's order and lists
  the values in C order by hand; the Python tests compare `write_npy` with `numpy.save` and
  `read_npy_2d` with `numpy.load`.

## Consequences

- The 2147483591 limit is `Array.MaxLength`, the largest dimension .NET allocates for a
  rectangular array: `new double[0, 2147483647]` throws (measured on .NET 10). It applies in both
  languages so both reject the same files, even though NumPy itself could build a `(0, 2**40)`
  array.
- Shared vectors pass 2-D values flat, in C order, with a separate `shape`, so empty rows, empty
  columns and complex values need no nested JSON.
