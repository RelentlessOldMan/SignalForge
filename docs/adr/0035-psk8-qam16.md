# ADR 0035: 8-PSK and 16-QAM

Status: accepted, 2026-11-13

## Context

QPSK is the only constellation so far. 8-PSK and 16-QAM are the next most used, and every
standard labels them differently (DVB-S2's 8-PSK starts at π/4 and is not a plain Gray code;
802.11's 16-QAM puts bit 0 on the negative side). Two implementations agree only if the
rotation, the labels, the scale and the tie rules are written down.

## Decision

- 8-PSK: point `p` at `e^{jπp/4}`, label `p ⊕ (p >> 1)` (the binary-reflected Gray code), bits
  MSB first. Hard decision by the nearest angle; 0 decides `000`.
- 16-QAM: the product of two Gray 4-PAM axes, `I` from the first bit pair, `Q` from the second;
  per axis `(1 − 2·first)·(3 − 2·second)`, so, as in QPSK, a first bit of 0 is positive.
  Divided by `√10`. Hard decision by thresholds `0` and `2/√10`, with the ties written in the
  conventions.
- Names `psk8_map`, `psk8_demap_hard`, `qam16_map`, `qam16_demap_hard`, next to the QPSK pair; no
  generic `M`-ary API yet.

## Consequences

- Neither is a particular standard's labelling; a standard's mapping would be its own function.
- The 8-PSK decision depends on `atan2`, whose last bit may differ between math libraries, so the
  vectors keep away from sector boundaries; 16-QAM's thresholds are exact.
- Expected values are by hand: every label's point, and decisions on hand-placed symbols.
