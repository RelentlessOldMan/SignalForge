# ADR 0055: WAV files

Status: accepted, 2026-11-13

## Context

SigMF (ADR 0012) suits RF recordings but almost no audio tool reads it. WAV is what sound cards,
audio analyzers and most DSP tools exchange, and its PCM and IEEE float layouts are simple enough
to read and write by hand with no dependency. A WAV file can hold several channels, while a
`Signal` is one-dimensional.

## Decision

- `write_wav(path, channels, sample_format="f32")` and `read_wav(path)` in `signalforge.files`
  (C# `SignalFiles.WriteWav` / `ReadWav`). A file maps to a list of real signals, one per channel,
  all with the same sample rate and length. Writing takes one `Signal` or a non-empty list.
  Complex signals are rejected: putting I and Q into two channels is a choice the caller makes
  explicitly, with two signals.
- Sample formats `u8`, `i16`, `i24`, `i32` (PCM) and `f32`, `f64` (IEEE float), named like the
  type part of the SigMF datatypes. Integer scaling, rounding and range rules are the SigMF ones
  (full scale 1.0, nothing clipped silently); `u8` is offset by 128 as WAV requires. The default is
  `f32`: it holds full scale and beyond, and audio tools read it.
- Writing produces one fixed layout: `RIFF`/`WAVE`, a 16-byte PCM `fmt ` chunk (format 1) or an
  18-byte float one (format 3, `cbSize` 0) followed by a `fact` chunk, then `data`. It never
  writes `WAVE_FORMAT_EXTENSIBLE`; readers accept plain PCM with any channel count. One layout
  makes the bytes a shared vector.
- Reading accepts what other tools write: formats 1, 3 and `WAVE_FORMAT_EXTENSIBLE` with the PCM
  or float sub-format, chunks it does not know (skipped, with their pad byte), and a RIFF size that
  is wrong. It rejects anything it cannot read exactly: compressed formats, other bit depths, a
  block size that does not match, a data chunk that is not whole frames or runs past the file.
- Only samples and the sample rate survive a WAV file. The sample rate must be a whole number of
  hertz that fits the 32-bit field; units, impedance, center frequency, time origin and metadata are
  not stored. Reading sets units to `"FS"`, the full scale the samples are scaled to.

## Consequences

- Audio captured elsewhere can be measured directly, and signals made here can be played.
- A non-integer sample rate cannot go into a WAV file; resample or use SigMF.
- Files written here and by Python's `wave` module are byte for byte the same for PCM with an even
  data size (`wave` does not write the pad byte), which the vector generator checks.
